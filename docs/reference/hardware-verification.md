# Hardware verification

What is proven on real hardware, so the support matrix's *verified* entries can be
traced: per area, the model and firmware, the method and the result. Model and
firmware only — never a serial.

The mark column: ✓ verified, – observed but not establishing the meaning (or only
partly), ✗ a negative result. **Library** means through this package. **Probe
client** means a standalone client speaking the same protocol to the same hardware;
its write + read-back results count as verification. `tests/devices` checks that
every *verified* capability has a ✓ row here. Settings carry no grade; their rows
record what was written and read back. Some rows name settings by the library's
hand-written keys rather than the generated settings files' keys; the parameter id in
each row identifies the setting.

Methods named in the rows: **write + read-back** (the library confirms the value from
the station), **independent dump** (a separate parameter dump diffed against the one
before), **restore** (written back to the start value and read back), **app display**
(the eufy app's screen read with the value in place), **live capture of the wire**
(the traffic on the LAN or Wi-Fi recorded and decoded).
